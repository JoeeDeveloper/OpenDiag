# KWP2000 (ISO 14230)

Keyword Protocol 2000, on K-line (this page) or carried over [TP2.0](tp20.md) on CAN. Code:
`crates/opendiag-proto/src/kwp/` (framing, K-line client, shared services, virtual module).

## K-line framing (ISO 14230-2)

```
Fmt  Tgt  Src  [Len]  Data...  Checksum
```

- `Fmt` = `0b10xxxxxx` (physical) or `0b11xxxxxx` (functional) addressing, low 6 bits = data length 1..63. A length of 0
  there means an extra `Len` byte follows (up to 255).
- The checksum is the sum of all preceding bytes modulo 256.
- The "no address" and CARB header forms are rejected, not guessed.
- The stream parser accepts bytes in any chunking, including one at a time and back to back. After a checksum or
  header error it discards its buffer so the stream can resynchronise.

K-line cables echo every byte sent. The echo parses as a message whose source is the tester, so the client ignores it
(and any other module's traffic).

## Starting communication

**Fast init** (`Transport::fast_init`): hold TX low for 25 ms, then high for 25 ms (the serial driver uses a break
signal with sub-millisecond timing), flush the break byte that appears on RX, then send StartCommunication (`0x81`).
The module answers `0xC1` with two key bytes. 5-baud slow init is a different path; see [kw1281.md](kw1281.md).

## Services

Written once, in the `KwpService` trait, and shared with the TP2.0 client:

`StartDiagnosticSession 0x10`, `TesterPresent 0x3E`, `ReadECUIdentification 0x1A`, `ReadDataByLocalIdentifier 0x21`,
`ReadDiagnosticTroubleCodesByStatus 0x18`, and the **gated** `ClearDiagnosticInformation 0x14`. The K-line client also
has the **gated** `WriteDataByLocalIdentifier 0x3B` and `SecurityAccess 0x27` (no algorithms bundled), and
`StopCommunication 0x82`, sent when a session ends.

Responses, `0x78` response-pending and negative responses behave as in [uds.md](uds.md) (same `P2` / `P2*` defaults).

## What `scan` and `dtc` assume (unverified for VAG modules)

- After connecting, a diagnostic session with mode `0x89` is requested (the mode in the public TP2.0 capture). A module
  that refuses it is still used.
- Identification is `ReadECUIdentification` option `0x9B`, shown as raw printable text with no part number claimed,
  because the field layout is not known.
- Fault codes (`0x18`, status 0, group `0xFF00`) are shown as 5-digit decimals with the raw status byte, like KW1281.

## Not verified

No KWP2000 module has been tested. Inter-byte and inter-message timing (P1 to P4) is left to the serial driver.
